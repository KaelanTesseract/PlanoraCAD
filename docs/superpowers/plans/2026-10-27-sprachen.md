# Sprachen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PlanoraCAD in Deutsch und Englisch, weitere Sprachen über `.ftl`-Dateien ohne Programmieren.

**Architecture:** Neue Crate `planora-i18n` ganz unten im Abhängigkeitsbaum: eingebaute `de.ftl`/`en.ftl`, zusätzliche Sprachen aus Ordnern, aktuelle Sprache global plus Überschreibung je Thread (`with_lang`). Alle Crates holen Texte per `tr!`. Arbeitsthreads übernehmen die Sprache des startenden Threads; so folgen Export (Export-Sprache) und Protokoll (immer Englisch) demselben Mechanismus.

**Tech Stack:** Rust, egui 0.36, `fluent-bundle` (concurrent bundle), `unic-langid`, windows-sys (`Win32_Globalization`).

**Spec:** `docs/superpowers/specs/2026-10-27-sprachen-design.md`

## Global Constraints

- Deutsch bleibt Wort für Wort wie vorher (Spec Ziel 8); alle bestehenden Tests laufen unverändert mit Deutsch, außer wo ein Konstanten-Text zur Funktion wird (dann nur der Aufruf im Test, nie der erwartete Text).
- Vor `set_global` gilt Deutsch (damit Tests ohne Zutun deutsch laufen). `set_global` nur in `main` und in genau einer eigenen Testdatei mit einem einzigen Test.
- Fluent ohne Bidi-Isolierung (`set_use_isolating(false)`), sonst stehen unsichtbare Zeichen in Texten.
- Kommazahlen in Meldungen nie als Fluent-Zahl übergeben, sondern als Text aus `i18n::fmt_num`/`localize_decimal`; Fluent-Zahlen nur für ganze Zahlen (Mehrzahl).
- Schlüssel: Kleinbuchstaben mit Bindestrich, Präfix je Bereich (`settings-…`, `export-…`, `kernel-…`). Eine Datei je Sprache: `crates/planora-i18n/languages/de.ftl`, `en.ftl`, nach Bereichen mit `## Überschrift` gegliedert.
- Englisch: einfache Sprache, „you“, CAD-übliche Wörter (Sketch, Extrude, Revolve, Fillet, Chamfer, Constraint, Drawing, Sheet, Title block, Parts list), keine Markennamen fremder CAD-Programme.
- Protokolle, Absturzbericht, technische Teile der Rückmeldung, Zeilen in `planora-update.log`: immer Englisch (`i18n::with_lang(&i18n::english(), …)` oder englische Literale).
- Neue Abhängigkeiten nur mit `cargo deny check` grün; Lizenzen im Kommentar in `Cargo.toml` nennen wie bei `crc32fast`.
- Oberfläche bei 1920 × 1080 in beiden Sprachen ohne Abschneiden/Überlappen; kleinere Fenster nicht testen.
- Vom Benutzer eingegebene Texte und gespeicherte Formeltexte (`planora_feature::expr::number_text`) werden nie übersetzt oder umformatiert.
- Kommentare und Doku deutsch wie im Repo; `docs/uebersetzen.md` englisch.

## Review Focus

1. **Worker-Texte:** Meldungen aus Arbeitsthreads (STEP-Prüfung, Zeichnungs-Export, Vernetzen) erscheinen in der Sprache des Fensters, nicht im globalen Deutsch – Test in Task 2.
2. **Kaputte oder unvollständige Sprachdatei eines Übersetzers:** fehlende Schlüssel → Englisch, Syntaxfehler → Datei übergangen, kein Absturz, Vermerk im Protokoll – Tests in Task 1.
3. **Zahlen in festen Texten:** Literale wie „0,5 mm“ oder „höchstens 25 MB“ in deutschen Texten werden im Englischen zu „0.5 mm“; Platzhalter-Zahlen kommen über `fmt_num` – Platzhalter-Gleichheitstest in Task 3, Stichprobe je Bereichs-Task.
4. **Texte, die beim Anlegen gespeichert werden** (Rückgängig-Beschriftungen, vorgeschlagene Namen): bleiben in der Sprache ihres Entstehens; kein Absturz, keine Schlüssel-Ids sichtbar – Test in Task 6.
5. **Umschalten bei offenem Fenster:** alle sichtbaren Texte wechseln im nächsten Bild; keine im Zustand zwischengespeicherten Oberflächentexte – Test in Task 2.

```rust
pub struct Lang;                       // Clone (Arc innen), Debug
impl Lang { pub fn id(&self) -> &str; pub fn name(&self) -> String; pub fn decimal(&self) -> char; }
pub enum Arg<'a> { Text(Cow<'a, str>), Int(i64) }   // From<&str>, From<String>, From<i64/i32/u32/u64/usize>
pub fn t(id: &str) -> String;
pub fn t_args(id: &str, args: &[(&str, Arg)]) -> String;
#[macro_export] macro_rules! tr { ($id:literal) => …; ($id:literal, $($k:ident = $v:expr),+ $(,)?) => … }
pub fn current() -> Lang;              // Thread-Überschreibung, sonst global
pub fn set_global(lang: Lang);
pub fn with_lang<R>(lang: &Lang, f: impl FnOnce() -> R) -> R;   // verschachtelbar, stellt zurück (auch bei Panic)
pub fn german() -> Lang; pub fn english() -> Lang;
pub fn available() -> Vec<Lang>;       // eingebaute + geladene, nach name() sortiert
pub fn find(id: &str) -> Option<Lang>;
pub struct LoadProblem { pub file: PathBuf, pub message: String }   // message englisch
pub fn load_dir(dir: &Path) -> Vec<LoadProblem>;   // fehlender Ordner = keine Probleme
pub fn pick(saved: Option<&str>, system: &[String]) -> Lang;
pub fn fmt_num(v: f64, decimals: usize) -> String; // Verhalten wie sketch_view::format_number, Trenner der aktuellen Sprache
pub fn localize_decimal(s: &str) -> String;        // '.' → Trenner der aktuellen Sprache
pub fn parse_num(text: &str) -> Option<f64>;       // wie sketch_view::parse_number (Komma und Punkt)
```
Festlegungen: Bundle `fluent_bundle::concurrent::FluentBundle`, Isolierung aus. Jede `.ftl` enthält `language-name` (Eigenname) und `decimal-separator` (`,` oder `.`); ohne `language-name` ist die Datei ungültig. Sprach-Id = Dateiname ohne `.ftl` (BCP 47, z. B. `fr`, `pt-BR`); eine geladene Datei mit Id `de`/`en` ersetzt die eingebaute nicht (Problem melden). Rückfall: Sprache → Englisch → Id selbst. `pick`: gespeicherte Id, wenn vorhanden; sonst erste Systemsprache, deren volle Id oder erstes Subtag passt (`de-DE` → `de`); sonst Englisch.
